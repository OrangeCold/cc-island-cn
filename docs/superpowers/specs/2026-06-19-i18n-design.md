# cc-island-cn 国际化（中英双语 + 设置页语言切换）设计

- 日期：2026-06-19
- 状态：已批准，待 spec 审查
- 关联分支：`feat/feat_zh`

## 背景与目标

cc-island-cn 当前 UI 为**纯英文**（Swift 源码零中文字符，项目名与文档虽为中文化，但 App 界面一直是英文）。本次为其增加国际化能力：

- 用户可在灵动岛设置菜单选择语言：**跟随系统 / 简体中文 / English**。
- 全量本地化所有用户可见文案为中英双语。

## 关键决策

| 决策点 | 选择 | 说明 |
|--------|------|------|
| 默认语言策略 | **跟随系统 + 可手动覆盖** | 系统中文→默认中文，系统英文/其他→默认英文；用户可在设置手动锁定某种。贴合 macOS 双语用户习惯与 Apple 原生惯例。 |
| 翻译范围 | **全量本地化** | 约 70–90 条文案，集中在 `ToolResultViews`（31）、`ChatView`（12）、`NotchMenuView`（9）、`ClaudeInstancesView`（8）。避免切中文后工具结果仍英文的割裂感。 |
| 切换机制 | **方案 A：String Catalog + `AppleLanguages` + 重启生效** | 原生、零私有 API、维护成本最低、String Catalog 全功能可用。菜单栏常驻应用语言切换频率极低，重启代价可忽略。 |

排除的备选：方案 B（Bundle swizzle 热切换，私有 API 风险）、方案 C（自定义查找层热切换，改造面大且失去原生本地化能力）。

## 技术底座

**Xcode String Catalog（`Localizable.xcstrings`）** 为唯一本地化底座。

- 开发语言 `en`（与 pbxproj `developmentRegion = en` 一致）。
- 现有 `Text("…")` 字面量在 SwiftUI 中即 `LocalizedStringKey`，Xcode 会**自动抽取**为 String Catalog 的 key，英文 value 自动填好。
- 人工只需补 `zh-Hans` 列；**调用点几乎不改**（除非要规范化 key 命名，本设计不做）。
- 仅 `LocalizedStringKey` 字面量被抽取为可翻译 key；动态拼接内容（工具结果里的文件名、代码片段等）天然不纳入——即「全量本地化」= 覆盖全部固定 UI 文案的精确边界。
- 部署目标 macOS 15.6 远高于 String Catalog（macOS 14+）门槛，无兼容问题。

## 详细设计

### 1. 架构与组件

遵循项目现有分层（领域 / 桥接 / 表现），改动小且内聚。

#### 新增文件

- **`CcIslandCn/Resources/Localizable.xcstrings`**
  String Catalog，开发语言 `en`，含 `zh-Hans`。承载全部用户可见文案的翻译。

- **`CcIslandCn/Core/AppLanguage.swift`**
  语言领域逻辑（单一职责）。定义语言枚举与应用/重启逻辑，**不依赖 UI**：
  ```
  enum AppLanguage: String {
      case system          // rawValue "system" —— 跟随系统，不写 AppleLanguages
      case zhHans = "zh-Hans"
      case en              // rawValue "en"
  }
  ```
  - `func apply()`：按当前 case 写或清 `UserDefaults` 的 `AppleLanguages`（`.system` → removeObject；`.zhHans` → `["zh-Hans"]`；`.en` → `["en"]`）。
  - `static func relaunch()`：用 `NSWorkspace.shared.openApplication(at:)`（传入 `Bundle.main.bundlePath`）重启自身；成功后 `NSApp.terminate`，失败回调通知调用方。

#### 改动文件

- **`CcIslandCn/Core/Settings.swift`**
  沿用现有 `enum AppSettings` + `UserDefaults.standard` 模式，新增 `appLanguage` key 与计算属性：
  - `get`：`AppLanguage(rawValue:)`，失败（旧版无 key / 手改 plist 的非法值）→ 回退 `.system`。
  - `set`：写 `newValue.rawValue`。
  - key 命名沿用现有 `Keys` 私有命名空间。

- **`CcIslandCn/UI/Views/NotchMenuView.swift`**
  新增一行 `LanguagePickerRow`（复用现有 `PickerRow` / `ScreenPickerRow` 交互范式），三选一：跟随系统 / 简体中文 / English。
  - 选中后流程：写 `AppSettings.appLanguage` → `AppLanguage.apply()` → 弹确认 alert「语言将在重启后生效，是否立即重启？」→ 「立即重启」`relaunch()` / 「下次启动生效」则本次会话维持旧语言（偏好已写，下次启动自动生效）。
  - 行的 label / 选项文案本身也走 String Catalog 本地化。

- **`CcIslandCn.xcodeproj/project.pbxproj`**
  `knownRegions` 在现有 `(en, Base)` 基础上追加 `zh-Hans`。

- **`CcIslandCn/Info.plist`**
  新增 `CFBundleLocalizations` = `[en, zh-Hans]`。`CFBundleDevelopmentRegion` 可省略（pbxproj `developmentRegion = en` 已生效）。

#### 不改动

- Python hook（`Resources/claude-island-state.py`）：输出为 JSON 协议字段与非 UI reason 字符串，无本地化需求。
- `SessionStore` 状态机、灵动岛窗口点击穿越逻辑、Sparkle 更新机制：与语言无关。

### 2. 数据流

```
启动:
  AppSettings.appLanguage 默认 .system
    → 不写 AppleLanguages
    → Bundle 按系统语言解析 .xcstrings（中文系统→zh-Hans；英文/其他→回退 en）

切换到「简体中文」:
  写 appLanguage = .zhHans
    → apply(): UserDefaults "AppleLanguages" = ["zh-Hans"]
    → 弹确认 alert
    → 用户「立即重启」→ relaunch()
    → 重启后 Text 全部按 zh-Hans 解析

切换到「English」:
  "AppleLanguages" = ["en"] → relaunch

切回「跟随系统」:
  removeObject(forKey: "AppleLanguages") → relaunch → 回归系统语言

解析 (SwiftUI 原生):
  Text(key) 启动时按当前 Bundle 语言查 .xcstrings
    命中 zh-Hans → 中文
    未命中 → 回退 en (开发语言，Xcode 原生行为，不崩)
```

### 3. 错误处理与边界

| 场景 | 处理 |
|------|------|
| relaunch 失败 | `openApplication` completion 的 error 非空 → 不 terminate，提示「请手动退出重开」，不静默丢弃。 |
| 无效 appLanguage 值 | 旧版升级（无 key）或手改 plist 的非法值 → `AppLanguage(rawValue:)` 失败 → 回退 `.system`。 |
| 缺失 key 回退 | 某 key 未填 zh-Hans → 自动回退 en（Xcode 原生），不崩、不报错。 |
| LSUIElement relaunch | 用 `NSWorkspace.shared.openApplication`（而非 `NSApp` 再入），避免 accessory 窗口状态异常；relaunch 前确认 Sparkle 未在更新中，避免冲突。 |
| 并发 | `AppSettings` 走线程安全的 `UserDefaults`，无新增并发面。 |

### 4. 测试与验证

项目**无测试套件**（无 `Tests/` 目录）。验证策略以**手动验证清单**为主。纯逻辑（`AppLanguage` 枚举 rawValue 往返、`apply()` 的 UserDefaults 写入）极薄，单测性价比低，**默认不做**；如需补，可将 `UserDefaults` 注入以测 `apply()`。

手动验证清单：

1. 系统中文 + `appLanguage = system` → 启动即中文
2. 系统英文 + `appLanguage = system` → 启动即英文
3. 切「简体中文」→ 提示重启 → 重启后全中文
4. 切「English」→ 重启后全英文
5. 切回「跟随系统」→ 重启后回系统语言
6. 抽查翻译完整性，重点文件：
   - `ToolResultViews`（工具结果碎片状态文案）
   - `ChatView`（Allow/Deny 审批、needs input 提示）
   - `UpdateRow`（更新状态：Up to date / Retry / On / Off 等）
   - `ClaudeInstancesView`（No sessions / Go to Terminal）
7. 旧用户升级（无 appLanguage key）→ 默认 `.system`，无异常
8. relaunch 失败路径 → 出现手动重启提示（可通过临时破坏 openApplication 触发，或代码审查确认分支）

**完整链路验证前提**：需本机装有 Claude Code CLI 并有活跃会话，App 才能收到 socket 事件与 JSONL 数据（CLAUDE.md 约定）。

## 范围外（YAGNI）

- 不做日文等其他语言（String Catalog 天然可扩展，未来补对应 `.lproj` / xcstrings 列即可）。
- 不做无重启热切换（方案 B/C 已排除）。
- 不本地化 Python hook。
- 不规范化现有 key 命名（保持英文字面量直接作 key，迁移成本最低）。
