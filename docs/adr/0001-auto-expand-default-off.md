# 灵动岛自动展开默认关闭，权限请求改用收起态专属符号

原行为：会话「需要注意」（任务完成 `.waitingForInput` / 权限请求 `.waitingForApproval`）时，灵动岛自动展开面板。用户反馈「任务完成后总自动弹出」打扰。决定：新增「自动展开」开关并**默认关闭**，一刀切断完成与权限的自动展开；完成态的轻提示（通知音、弹跳、30 秒对勾）原样保留；权限请求**不**补通知音/弹跳，改为收起态右侧专属 `hand.tap` 符号（与转圈/对勾三态并列），并移除原有的左侧琥珀图标。取舍：权限审批的感知从「展开面板」降级为「收起态符号」，但因主力用户在终端即可看到 Claude Code 的权限请求、岛的符号是辅助而非唯一通道，可接受。

## 考虑过但拒绝的方案

- **只关完成弹出、保留权限弹出**：拒绝。用户明确不想要任何自动弹出面板。
- **一刀切 + 给权限补通知音/弹跳**：拒绝。通知音与弹跳当前无法区分「完成」与「权限」（优先级不同：完成可忽略、权限必须响应），且放开会让权限请求钻进 `handleWaitingForInputChange`、污染其完成专属逻辑（`waitingForInputTimestamps` 字典、30 秒对勾周期）。

## 后果

- 默认关闭属 breaking change：现有用户升级后，会话完成与权限请求都不再自动展开面板。
- 权限请求变为纯视觉提示：用户不看刘海（且不在终端）时可能感知不到，依赖终端侧的 Claude Code 自身提示作为兜底。
